## Spec

- Document: [NIST SP 800-186](https://doi.org/10.6028/NIST.SP.800-186), February 2023. Section: 3.2.1.3, the curve P-256.
- Document: [SEC 1 version 2.0](https://www.secg.org/sec1-v2.pdf), May 2009. Sections: 2.3.3 and 2.3.4 (uncompressed points), 3.2.1 (public keys), 4.1.3 and 4.1.4 (ECDSA).
- Document: [RFC 6979](https://www.rfc-editor.org/rfc/rfc6979), August 2013. Section: 3.2, with HMAC-SHA-256 and qlen = 256.
- Use: the self-signed certificates of [libp2p TLS](https://github.com/libp2p/specs/blob/c750236de43cd8b246a824b377dfdb26bae686db/tls/tls.md) carry ECDSA P-256 keys in go-libp2p v0.50.0, rust-libp2p `libp2p-tls` 0.7.0, jvm-libp2p 1.3.8 and nim-libp2p, which consensus clients use for QUIC; TLS 1.3 signs with them as `ecdsa_secp256r1_sha256`.
- The design follows [secp256k1.md](secp256k1.md): the same `PrivateKey`, `Hash`, `Signature`, `Valid`, `Number`, `ProjectivePoint` and `Modulus` types, with the P-256 constants. P-256 has no low s rule: `crypto_p256_sign` writes s as computed, and `crypto_p256_verify` takes any s from 1 to n - 1.

## Function `crypto_p256_public_key`

Writes the uncompressed public key d * G of a private key d.

### Signature

```
crypto_p256_public_key(private_key, public_key) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `private_key` | input | [`PrivateKey`](secp256k1.md#type-privatekey) |
| `public_key` | output | `P256PublicKey` |

### Returns

- `CRYPTO_OK`: `public_key` holds 0x04, x and y.
- `CRYPTO_INVALID_PRIVATE_KEY`: d is 0, or n or more. Nothing is written.

### Caller must

- Keep `public_key` apart from `private_key`.

### Function does

- Computes d * G with `crypto_p256_point_mul`, then x and y with `crypto_p256_point_affine`.

### Function never

- Writes more than `public_key` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.
- Branches or picks an address based on the bits of d.

### Limits

- Stack: 1272 bytes on x86-64 (return address included), 1312 bytes on ARM64, 1392 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_p256_public_key` (`_crypto_p256_public_key` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `private_key`, `public_key`.

## Function `crypto_p256_sign`

Signs a hash with ECDSA and a nonce from RFC 6979, and writes r and s.

### Signature

```
crypto_p256_sign(private_key, hash, signature) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `private_key` | input | [`PrivateKey`](secp256k1.md#type-privatekey) |
| `hash` | input | [`Hash`](secp256k1.md#type-hash) |
| `signature` | output | [`Signature`](secp256k1.md#type-signature) |

### Returns

- `CRYPTO_OK`: `signature` holds r and s.
- `CRYPTO_INVALID_PRIVATE_KEY`: d is 0, or n or more. Nothing is written.

### Caller must

- Keep `signature` apart from the inputs.

### Function does

- Takes e = the hash as a big-endian number, mod n.
- Draws k by RFC 6979 section 3.2 with key d and input e, with `crypto_hmac_sha256`. It skips a k that is 0 or n or more, and a k that gives r = 0 or s = 0, as step h says.
- Computes r = x(k * G) mod n and s = (e + r * d) / k mod n.

### Function never

- Writes more than `signature` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.
- Branches or picks an address based on the bits of d or k. Only whether a k is usable decides a branch.

### Limits

- Stack: 1992 bytes on x86-64 (return address included), 2032 bytes on ARM64, 2112 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_p256_sign` (`_crypto_p256_sign` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `private_key`, `hash`, `signature`.

## Function `crypto_p256_verify`

Checks an ECDSA signature of a hash against an uncompressed public key.

### Signature

```
crypto_p256_verify(public_key, hash, signature, valid) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `public_key` | input | `P256PublicKey` |
| `hash` | input | [`Hash`](secp256k1.md#type-hash) |
| `signature` | input | [`Signature`](secp256k1.md#type-signature) |
| `valid` | output | [`Valid`](secp256k1.md#type-valid) |

### Returns

- `CRYPTO_OK`: `valid` holds 1 or 0.
- `CRYPTO_INVALID_PUBLIC_KEY`: `public_key` is not a valid uncompressed point. Nothing is written.

### Caller must

- Keep `valid` apart from the inputs.

### Function does

- Checks `public_key` with `crypto_p256_point_load` first.
- Writes 0 when r or s is 0 or n or more.
- Otherwise computes R = u1 * G + u2 * Q, with u1 = e / s and u2 = r / s mod n, and writes 1 when R is not the point at infinity and x(R) mod n = r.

### Function never

- Writes more than `valid` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.

### Limits

- Stack: 1816 bytes on x86-64 (return address included), 1856 bytes on ARM64, 1936 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_p256_verify` (`_crypto_p256_verify` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `public_key`, `hash`, `signature`, `valid`.

## Function `crypto_p256_point_load`

Checks an uncompressed public key, by SEC 1 section 2.3.4, and loads its point with Z = 1.

### Signature

```
crypto_p256_point_load(point, public_key) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `point` | output | [`ProjectivePoint`](secp256k1.md#type-projectivepoint) |
| `public_key` | input | `P256PublicKey` |

### Returns

- `CRYPTO_OK`: `point` holds the point.
- `CRYPTO_INVALID_PUBLIC_KEY`: the first byte is not 0x04, x or y is p or more, or y^2 is not x^3 - 3x + b mod p.

### Function does

- Turns x and y into Montgomery form, then compares y^2 with x^3 - 3x + b.

### Function never

- Writes more than `point` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 192 bytes on x86-64 (return address included), 224 bytes on ARM64, 240 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_p256_point_load`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `point`, `public_key`.

## Function `crypto_p256_point_mul`

Computes scalar * base.

### Signature

```
crypto_p256_point_mul(point, scalar, base) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `point` | output | [`ProjectivePoint`](secp256k1.md#type-projectivepoint) |
| `scalar` | input | [`Number`](secp256k1.md#type-number), plain |
| `base` | input | [`ProjectivePoint`](secp256k1.md#type-projectivepoint) |

### Function does

- Starts from the point at infinity. For each bit from 255 down: doubles, adds `base`, and keeps the sum where the bit is 1, through a mask.

### Function never

- Branches or picks an address based on the bits of `scalar`.
- Writes more than `point` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 352 bytes on x86-64 (return address included), 384 bytes on ARM64, 400 bytes on RISC-V.
- Point operations: 256 doublings and 256 additions.

### ABI

- Role: L0.
- Symbol: `crypto_p256_point_mul`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `point`, `scalar`, `base`.

## Type `P256PublicKey`

An uncompressed point, SEC 1 section 2.3.3, as certificates carry it.

### Layout

| Offset | Field | Type | Meaning |
|---|---|---|---|
| 0 | `prefix` | u8 | 0x04 |
| 1 | `x` | 32 bytes | x, a big-endian number |
| 33 | `y` | 32 bytes | y, a big-endian number |

### Rules

- 65 bytes. The buffer starts at a multiple of 8.
- Valid when the prefix is 0x04, x < p, y < p, and y^2 = x^3 - 3x + b mod p.

## Test vectors

- RFC 6979 section A.2.5, P-256 with SHA-256: the public key of the example key, and the signatures of "sample" and "test", signed and checked
  - File: [`rfc6979.txt`](https://www.rfc-editor.org/rfc/rfc6979.txt), SHA-256 `456e8f17558fdbd206f968b96fc6f1b4a71ea331ab30ad17f711ab3adaa7d701`.
- NIST CAVP FIPS 186-4 ECDSA, P-256: `KeyPair.rsp` (public keys), `PKV.rsp` (public key checks), `SigGen.rsp` with SHA-256 (as valid signatures) and `SigVer.rsp` with SHA-256
  - File: [`186-4ecdsatestvectors.zip`](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Algorithm-Validation-Program/documents/dss/186-4ecdsatestvectors.zip), SHA-256 `fe47cc92b4cee418236125c9ffbcd9bb01c8c34e74a4ba195d954bcb72824752`.
  - The hash is the SHA-256 of the message. `PKV.rsp` keys whose x or y needs more than 32 bytes are left out.
- Wycheproof ECDSA P-256 SHA-256, P1363 encoding
  - File: [`ecdsa_secp256r1_sha256_p1363_test.json`](https://github.com/C2SP/wycheproof/blob/65ca494727a52944c204441c860b039e6786b99b/testvectors_v1/ecdsa_secp256r1_sha256_p1363_test.json), SHA-256 `c60de693930e386c3a5472d08081623ef8504decc54b38ac01ec6b2a2575c986`.
  - The hash is the SHA-256 of the message. Signatures other than 64 bytes are left out.
- Generated cases
  - Private keys 1, 2, 3, n - 1, n - 2, (n - 1) / 2, (n + 1) / 2, 2^255, 2^128 + 1 and 150 random keys; 0, n, n + 1 and 2^256 - 1 as bad keys.
  - Signatures of 155 hashes, among them 0, 2^256 - 1, n, n - 1 and n + 5; each checked as is, with s replaced by n - s (still valid), with a flipped bit and against another hash; 10 of them also with r or s replaced by 0, n, or n plus the value.
  - Public keys with the prefixes 0x00, 0x02, 0x03, 0x05, 0x06, 0x07 and 0xFF, points off the curve, x or y of p or more, and the negated point.
  - The points with x from 1 to 39, and with y from 1 to 39, each also with p added to that coordinate, which must give `CRYPTO_INVALID_PUBLIC_KEY`. The generator finds x from y with the roots of x^3 - 3x + b - y^2.
  - Expected results: `cryptography` 50.0.2 (OpenSSL), pinned with hashes in [tests/generator/requirements.txt](../../tests/generator/requirements.txt), with its RFC 6979 signing (`deterministic_signing`).
