# SHA-512

## Contents

### Functions

- [`crypto_sha512`](#function-crypto_sha512): hashes a byte string.
- [`crypto_sha512_init`](#function-crypto_sha512_init): starts a hash in a state.
- [`crypto_sha512_update`](#function-crypto_sha512_update): takes more bytes into a state.
- [`crypto_sha512_final`](#function-crypto_sha512_final): pads and writes the digest.
- [`crypto_sha512_blocks`](#function-crypto_sha512_blocks): runs the hash computation on whole blocks.

### Types

- [`Sha512State`](#type-sha512state): a hash in progress.
- [`Sha512Digest`](#type-sha512digest): a SHA-512 result.

## Spec

- Document: [FIPS 180-4](https://doi.org/10.6028/NIST.FIPS.180-4), August 2015.
- Sections: 4.1.3 and 4.2.3 (functions and constants), 5.1.2 (padding), 5.3.5 (initial hash value), 6.4 (the hash computation).
- Use: Ed25519 hashes with SHA-512 ([ed25519.md](ed25519.md)).

## Function `crypto_sha512`

Hashes the bytes in a [`ByteList`](sha-256.md#type-bytelist) with SHA-512 and writes the result to a `Sha512Digest`.

### Signature

```
crypto_sha512(message, digest) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `message` | input | [`ByteList`](sha-256.md#type-bytelist) |
| `digest` | output | `Sha512Digest` |

### Returns

- `CRYPTO_OK`, always.

### Caller must

- Pass a valid `ByteList` in `message`. It is not checked.
- Keep `digest` apart from `message`.

### Function does

- Runs `crypto_sha512_init`, `crypto_sha512_update` and `crypto_sha512_final` on a state on its own stack.

### Function never

- Reads more than the `ByteList` header and its `count` bytes.
- Writes more than `digest` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.
- Branches or picks an address based on message bytes.

### Limits

- Stack: 1040 bytes on x86-64 (return address included), 1040 bytes on ARM64, 1184 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_sha512` (`_crypto_sha512` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `message`, `digest`.

## Function `crypto_sha512_init`

Sets a state to the initial hash value, with no bytes taken.

### Signature

```
crypto_sha512_init(state) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `state` | output | `Sha512State` |

### Returns

- `CRYPTO_OK`, always.

### Function does

- Sets H to H(0) of section 5.3.5 and `count` to 0.

### Function never

- Writes more than the `h` and `count` fields of `state`.
- Makes an OS call.

### Limits

- Stack: 8 bytes on x86-64, its return address, and none on ARM64 and RISC-V.

### ABI

- Role: L2.
- Symbol: `crypto_sha512_init` (`_crypto_sha512_init` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `state`.

## Function `crypto_sha512_update`

Takes the bytes of a `ByteList` into a state, after the bytes it already took.

### Signature

```
crypto_sha512_update(state, message) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `state` | state | `Sha512State` |
| `message` | input | [`ByteList`](sha-256.md#type-bytelist) |

### Returns

- `CRYPTO_OK`, always.

### Caller must

- Pass a state from `crypto_sha512_init` or from this function.
- Pass a valid `ByteList` in `message`. It is not checked.
- Keep `state` apart from `message`.
- Keep the total below 2^64 bytes.

### Function does

- Fills the buffer of `state` first; when it holds 128 bytes, runs `crypto_sha512_blocks` on it.
- Runs `crypto_sha512_blocks` straight on the whole blocks of the message that follow.
- Keeps the last bytes, fewer than 128, in the buffer.
- Adds the `count` of `message` to the `count` of `state`.

### Function never

- Reads more than the `ByteList` header and its `count` bytes.
- Writes more than `state` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.
- Branches or picks an address based on message bytes.

### Limits

- Stack: 768 bytes on x86-64 (return address included), 736 bytes on ARM64, 864 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_sha512_update` (`_crypto_sha512_update` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `state`, `message`.

## Function `crypto_sha512_final`

Pads the bytes taken, as section 5.1.2 says, and writes the digest.

### Signature

```
crypto_sha512_final(state, digest) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `state` | state | `Sha512State` |
| `digest` | output | `Sha512Digest` |

### Returns

- `CRYPTO_OK`, always.

### Caller must

- Pass a state from `crypto_sha512_init` or `crypto_sha512_update`.
- Keep `digest` apart from `state`.

### Function does

- Adds the 0x80 byte, zeros, and the length in bits as a 128-bit big-endian number, in one or two blocks.
- Writes H0 to H7 big endian to `digest`.
- Leaves `state` holding the final hash value. A new hash starts with `crypto_sha512_init`.

### Function never

- Writes more than `state`, `digest` and its own stack.
- Makes an OS call.
- Branches or picks an address based on message bytes.

### Limits

- Stack: 768 bytes on x86-64 (return address included), 736 bytes on ARM64, 864 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_sha512_final` (`_crypto_sha512_final` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `state`, `digest`.

## Function `crypto_sha512_blocks`

Runs the hash computation of section 6.4.2 on whole 128-byte blocks.

### Signature

```
crypto_sha512_blocks(h, data, count) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `h` | state | the `h` field of a `Sha512State` |
| `data` | input | `count` × 128 bytes |
| `count` | input | u64 in a register |

### Caller must

- Keep `h` apart from `data`.

### Function does

- For each block: builds W[0..79] with section 6.4.2 step 1, runs the 80 rounds, and adds the result to H.
- Reads `data` with loads of any alignment on x86-64 and ARM64, and a byte at a time on RISC-V.

### Function never

- Writes more than `h` and its own stack.
- Makes an OS call.
- Branches or picks an address based on the data.

### Limits

- Stack of its own: 704 bytes on x86-64 (return address included), 640 bytes on ARM64, 752 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_sha512_blocks`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `h`, `data`, `count`.

## Type `Sha512State`

A hash in progress: the hash value, the bytes taken, and the bytes after the last whole block.

### Layout

| Offset | Field | Type | Meaning |
|---|---|---|---|
| 0 | `h` | 8 × u64 | H0 to H7, little endian |
| 64 | `count` | u64 | Bytes taken so far |
| 72 | `buffer` | 128 bytes | The last `count` mod 128 bytes taken |

### Rules

- 200 bytes, at a multiple of 8. `CRYPTO_SHA512_STATE_SIZE` in [include/sha512.inc](../../include/sha512.inc).
- It holds message bytes.

## Type `Sha512Digest`

A SHA-512 result.

### Layout

| Offset | Field | Type | Meaning |
|---|---|---|---|
| 0 | `h` | 8 × u64, big endian | H0 to H7 from FIPS 180-4 |

### Rules

- 64 bytes, at a multiple of 8.

## Test vectors

- NIST CAVP byte vectors: `SHA512ShortMsg.rsp` and `SHA512LongMsg.rsp`
  - File: [`shabytetestvectors.zip`](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Algorithm-Validation-Program/documents/shs/shabytetestvectors.zip), SHA-256 `929ef80b7b3418aca026643f6f248815913b60e01741a44bba9e118067f4c9b8`.
- Generated messages
  - Every length from 0 to 300 bytes, the block edges up to 100000 bytes, and all-zero and all-ones messages at the padding edges.
  - Expected results: Python `hashlib.sha512`.
- The runner hashes each message with `crypto_sha512`, then in three parts with `crypto_sha512_init`, `crypto_sha512_update` and `crypto_sha512_final`.
