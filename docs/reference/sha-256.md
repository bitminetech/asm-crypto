## Spec

- Document: [FIPS 180-4](https://doi.org/10.6028/NIST.FIPS.180-4), August 2015.
- Section: 6.2.

## Function `crypto_sha256`

Hashes the bytes in a `ByteList` with SHA-256 and writes the result to a `Digest`.

### Signature

```
crypto_sha256(message, digest) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `message` | input | `ByteList` |
| `digest` | output | `Digest` |

### Returns

- `CRYPTO_OK`, always.

### Caller must

- Pass a valid `ByteList` in `message`. It is not checked.
- Pass a `Digest` in `digest`.
- Keep `message` and `digest` apart. They must not overlap.

### Function does

- Hashes the `count` bytes that start at `offset`.
- Writes the result to `digest`.
- Ignores what `digest` held before.

### Function never

- Reads more than the `ByteList` header and its `count` bytes.
- Writes more than `digest` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.
- Branches or picks an address based on message bytes. Message bytes may be secret.

### Limits

- Stack: 512 bytes on x86-64 (return address included), 416 bytes on ARM64, 480 bytes on RISC-V.
- Blocks hashed: `floor((count + 8) / 64) + 1`.
- Message size: always below the FIPS limit of 2^64 bits.

### ABI

- Role: L2.
- Symbol: `crypto_sha256` (`_crypto_sha256` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `message`, `digest`.

## Type `ByteList`

A byte string with a 24 byte header.

### Layout

| Offset | Field | Type | Meaning |
|---|---|---|---|
| 0 | `size` | u64 | Total buffer size in bytes |
| 8 | `offset` | u64 | Where the bytes start, from the buffer start |
| 16 | `count` | u64 | Number of bytes in use |

### Rules

- u64 is 8 bytes, little endian.
- The buffer starts at a multiple of 8.
- `offset` is at least 24 and a multiple of 8.
- `offset + count` is at most `size`.
- Bytes after `count` are unused. Functions do not read them.

## Type `Digest`

A SHA-256 result.

### Layout

| Offset | Field | Type | Meaning |
|---|---|---|---|
| 0 | `h` | 8 × u32, big endian | H0 to H7 from FIPS 180-4 |

### Rules

- 32 bytes.
- The buffer starts at a multiple of 8.
