# 6.2 SHA-256

Spec: [FIPS 180-4](https://doi.org/10.6028/NIST.FIPS.180-4), section 6.2, with the functions in section 4.1.2, the constants in section 4.2.2, the padding in section 5.1.1, the parsing in section 5.2.1 and the initial hash value in section 5.3.3.

### `ByteList`

Layout revision 1. This is a standalone list with one field, as ARCHITECTURE.md section 6 defines it. The fixed fields use 24 bytes. The buffer and the byte part start at addresses that are multiples of 8.

- `size` This unsigned 8-byte number gives the total buffer size in bytes.
- `offset` This unsigned 8-byte number gives the start of the byte part, in bytes from the buffer start.
- `count` This unsigned 8-byte number gives the number of bytes in use in the byte part.

A `ByteList` is well formed when `offset` is at least 24, `offset` is a multiple of 8, `offset` is at most `size`, and `count` is at most `size` minus `offset`. The bytes after `count` in the byte part are unused room. The function does not read them.

### `Digest`

Layout revision 1. This is a fixed-size value of 32 bytes with no size header. The buffer starts at an address that is a multiple of 8.

- `bytes` These 32 bytes hold the hash value H0 to H7 of FIPS 180-4, with each 4-byte word in big-endian byte order.

### `crypto_sha256(message, digest)`

- `message` This input is a well-formed `ByteList` that holds the message, and the function does not validate it.
- `digest` This output is a `Digest` buffer of 32 bytes that receives the hash value.

Requirements: The caller supplies a well-formed `ByteList` in `message`. Its accessible extent is `size` bytes from the `message` pointer. The caller supplies a `Digest` buffer of 32 accessible bytes in `digest`. The `digest` bytes do not overlap the `message` bytes. The function computes SHA-256 of the `count` bytes that start at `offset`, as FIPS 180-4 section 6.2 defines it, and writes the 32-byte result to `digest`. The message length limit of FIPS 180-4 (fewer than 2^64 bits) always holds, because a well-formed buffer on every supported target is smaller than 2^57 bytes. The function reads only the 24 fixed bytes and the `count` bytes of the message. It writes only the 32 digest bytes and its own stack. The previous contents of `digest` do not change the result. The message bytes can be secret. `count` and the pointer values are public. Branches and memory addresses depend only on public data.

ABI: The core ABI of ARCHITECTURE.md section 6 for each ISA. The symbol is `crypto_sha256` (`_crypto_sha256` in Mach-O). The pointer arguments are `message`, then `digest`. There is no native adapter.

Effects and ownership: The function is effect-free. It has no state, no resource context and no operation boundary. It keeps no pointer after it returns.

Bounds: The function processes `floor((count + 8) / 64) + 1` blocks of 64 bytes. It uses at most 1024 bytes of stack, including its callees. It uses no scratch buffer. The modeled instruction bound is not yet recorded.

Outputs: `digest`, 32 bytes, laid out as `Digest`.

Status: The function returns `0` for every input that meets the requirements. It has no failure codes.
