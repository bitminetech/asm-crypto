## Spec

- Document: [cryptography-specs v0.3.0](https://github.com/ethereum/cryptography-specs/tree/bb6dfe55198243682bc2eaf94611af2dbce1be6f/EthLib/Cryptography/Bls), commit `bb6dfe55198243682bc2eaf94611af2dbce1be6f`.
- Section: `Fp.lean`, `Fp2.lean`, `Fp6.lean`, `Fp12.lean`, `Fr.lean` (the fields), `G1.lean`, `G2.lean` (the groups), `Pairing.lean` (the optimal ate pairing and the pairing check), `Compress.lean` (the compressed forms, decompression and the subgroup checks), and `Exports/Bls.lean` (`decodeG1Export`, `decodeG2Export`).
- p = 0x1a0111ea397fe69a4b1ba7b6434bacd764774b84f38512bf6730d2a0f6b0f6241eabfffeb153ffffb9feffffffffaaab.
- r = 0x73eda753299d7d483339d80809a1d80553bda402fffe5bfeffffffff00000001.
- E1: y^2 = x^3 + 4 over Fp. E2: y^2 = x^3 + 4 (1 + u) over Fp2 = Fp[u]/(u^2 + 1).
- G1 and G2 are the subgroups of order r. The check of the spec is r * P = O.
- Use: consensus-specs `313cbfe`, `specs/altair/beacon-chain.md`, `process_sync_aggregate`, calls `bls.bytes48_to_G1`, `bls.add`, `bls.neg` and `bls.G1_to_bytes48` to subtract the keys of the members that did not take part.

## The x variant

On x86-64, `libasm-crypto-sha.a` (sha-256.md, The `sha` variant) holds `asm/core/x86_64/bls12381x.s` in place of `bls12381.s`: the same source with `CRYPTO_ADX` set, so crypto_bls_fp_mul uses `mulx` (BMI2) and the carry chains of `adcx` and `adox` (ADX). Every other function is the same code.

| ISA | Extra instructions | Feature check, on top of the `sha` variant's |
|---|---|---|
| x86-64 | BMI2 and ADX | CPUID leaf 7 subleaf 0 EBX bit 8 (BMI2) and bit 19 (ADX) |

- `runner-sha` runs every vector on it, and prints SKIP on a CPU without these features.
- Proof claims cover only `libasm-crypto.a`.

## Function `crypto_bls_g1_decode`

Reads a compressed point of E1 and checks that it lies in G1 (`decodeG1Export`).

### Signature

```
crypto_bls_g1_decode(bytes, point) -> status
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `bytes` | input | `G1Compressed` |
| `point` | output | `G1Point` |

### Returns

- `CRYPTO_OK`: `point` holds the point; the point at infinity is accepted in its one form.
- `CRYPTO_INVALID_ENCODING`: the bytes break a rule of `G1Compressed`, x is not the x of a point of E1, or the point is not in G1. Nothing is written.

### Caller must

- Keep `point` apart from `bytes`.

### Function does

- Decompresses the bytes with `crypto_bls_g1_uncompress`.
- Checks that r times the point is the point at infinity.

### Function never

- Reads more than `bytes`.
- Writes more than `point` and its own stack.
- Keeps a pointer after it returns.
- Makes an OS call.

### Limits

- Stack: 2368 bytes on x86-64 (return address included), 2496 bytes on ARM64, 2624 bytes on RISC-V, callees included.

### ABI

- Role: L2.
- Symbol: `crypto_bls_g1_decode` (`_crypto_bls_g1_decode` on macOS).
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6).
- Argument order: `bytes`, `point`.

## Function `crypto_bls_fp_mul`

Computes a * b / 2^384 mod p, the Montgomery product (`Fp.mul`).

### Signature

```
crypto_bls_fp_mul(result, a, b) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `result` | output | `FpElement` |
| `a` | input | `FpElement`, or a number below 2^384 |
| `b` | input | `FpElement` |

### Function does

- Runs CIOS: for each limb b_i of b, adds a * b_i to T, then q * p with q = T_0 * (-p^-1 mod 2^64), and drops the low limb of T.
- Subtracts p once when T is p or more, which gives a number below p when b is below p.
- Writes `result` last, so it may be `a` or `b`.
- The x variant (The x variant): the same steps, each a * b_i and q * p with `mulx`, the low halves added with `adcx` and the high halves with `adox`.

### Function never

- Writes more than `result` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 64 bytes on x86-64 (return address included), 32 bytes on ARM64, 80 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_fp_mul`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `result`, `a`, `b`.

## Function `crypto_bls_fp_pow`

Computes base^e (`Fp.powNat`), for a public e.

### Signature

```
crypto_bls_fp_pow(result, base, exponent) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `result` | output | `FpElement` |
| `base` | input | `FpElement` |
| `exponent` | input | `FpLimbs`: e |

### Function does

- Writes the table base^0 to base^15 with `crypto_bls_fp_mul`.
- Writes 1 when e = 0.
- Otherwise starts from base^n for the top nibble n of e that is not 0, and for each lower 4-bit nibble n squares 4 times, then multiplies by base^n when n is not 0 (a fixed window of 4 bits).
- Gives base^e: each step takes acc to acc^16 base^n, which is the power for the bits read so far.
- Copies `base` into the table first, so `result` may be `base`.

### Function never

- Writes more than `result` and its own stack.
- Makes an OS call.

### Limits

## Function `crypto_bls_fp_inverse`

Computes 1 / a for a not 0, and 0 for a = 0: the result of `Fp.inverse`, a^(p - 2).

### Signature

```
crypto_bls_fp_inverse(result, a) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `result` | output | `FpElement` |
| `a` | input | `FpElement` |

### Function does

- Writes 0 when a is 0.
- Otherwise runs the binary extended Euclid algorithm, in variable time, on u = a and v = p, with b = R^2 mod p and d = 0, R = 2^384.
- Each step keeps b a = u R^2 and d a = v R^2 mod p:
  - while u is even, halves u, and b mod p (adds p first when b is odd);
  - while v is even, halves v, and d mod p;
  - then subtracts the smaller of u and v from the other, and d from b or b from d to match, mod p.
- Stops when u or v is 1, and writes b when u = 1, else d: R^2 / a mod p, which is 1 / a in Montgomery form for a in Montgomery form.
- Gives the result of a^(p - 2): p is prime, so 1 / a is the only inverse.
- Reads a before it writes, so `result` may be `a`.

### Function never

- Writes more than `result` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 160 bytes on x86-64 (return address included), 80 bytes on ARM64, 208 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_fp_inverse`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `result`, `a`.

## Function `crypto_bls_g1_in_subgroup`

Writes 1 when r P is the point at infinity, or P is (`G1.inSubgroup`), else 0.

### Signature

```

```

## Function `crypto_bls_g2_in_subgroup`

Writes 1 when r P is the point at infinity, or P is (`G2.inSubgroup`), else 0.

### Signature

```
crypto_bls_g2_in_subgroup(point, valid) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `point` | input | `G2Point` |
| `valid` | output | [`Valid`](secp256k1.md#type-valid) |

### Function does

- Writes 1 when P is the point at infinity.
- Otherwise computes t = |x| P = -x P, with `crypto_bls_g2_mul` and |x| = 0xd201000000010000.
- Writes 1 when psi(P) = x P = -t, else 0. psi(X, Y, Z) = (c1Psi conj(X), c2Psi conj(Y), conj(Z)), the psi of `crypto_bls_psi` in Jacobian coordinates.
- Compares in Jacobian coordinates: Xs Zt^2 = Xt Zs^2 and Ys Zt^3 = -Yt Zs^3, for psi(P) = (Xs, Ys, Zs) and t = (Xt, Yt, Zt). t at infinity gives 0.
- Gives the result of `G2.inSubgroup` for every point P of E2:

  - r P = O puts P in G2. On G2, psi is the multiplication by p, and p = x mod r, so the check gives 1.

- Writes more than `valid` and its own stack.
- Makes an OS call.

### Limits

## Function `crypto_bls_miller_double`

Runs the step of `millerDouble` that gives the line: the tangent line at T, valued at P, then T = 2 T.

### Signature

```
crypto_bls_miller_double(line, t, p, work) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `line` | output | 288 bytes: c0, c2 and c3, each an `Fp2Element` |
| `t` | state | `G2Point`: T |
| `p` | input | `G1Xy`: (xp, yp) |
| `work` | scratch | 768 bytes |

### Caller must

- Keep `line`, `t`, `p` and `work` apart from each other.

### Function does

- With T = (X, Y, Z) before the step: the line value c0 + c2 w^2 + c3 w^3 (`lineValue`), with c0 = 3 X^3 - 2 Y^2, c2 = -3 X^2 Z^2 xp and c3 = 2 Y Z^3 yp.
- Doubles T with the steps of `crypto_bls_g2_double` (dbl-2009-l): T stays when Z = 0; else with A = X^2, B = Y^2, C = B^2, D = 2 ((X + B)^2 - A - C), E = 3 A and F = E^2, T = (F - 2 D, E (D - (F - 2 D)) - 8 C, 2 Y Z).
- Takes A, B and E from the line, and computes 2 Y Z once for the line (c3 = (2 Y Z) Z^2 yp) and for the doubling, so T gets the same coordinates as from `crypto_bls_g2_double`.
- The caller squares f and multiplies it by the line: together that is `millerDouble`.

### Function never

- Writes more than `line`, `t` and `work` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 64 bytes on x86-64 (return address included), 96 bytes on ARM64, 112 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_miller_double`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `line`, `t`, `p`, `work`.

## Function `crypto_bls_miller_loop`

Computes the product of `millerLoop`(Q_i, P_i) over a list of pairs, for |x| = 0xd201000000010000, in one loop.

### Signature

```
crypto_bls_miller_loop(f, pairs, count, work) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `f` | output | `Fp12Element` |
| `pairs` | state | count entries of 576 bytes: Q_i = (xq, yq) as a `G2Xy` at 0, P_i = (xp, yp) as a `G1Xy` at 192, and the point T_i (a `G2Point`) at 288 |
| `count` | input | u64: at least 1 |
| `work` | scratch | 1056 bytes: the line, then the work of the steps |

### Caller must

- Pass count of 1 or more.
- Keep `f`, `pairs` and `work` apart from each other.

### Function does

- Starts from T_i = (xq, yq, 1) for each pair, and f = 1.
- For each bit of |x| below its top bit:
  - squares f with `crypto_bls_fp12_square`, except at the first bit, where f is 1;
  - for each pair, gets the line of the double step with `crypto_bls_miller_double`, and multiplies f by it with `crypto_bls_fp12_mul_line`;
  - when the bit is 1, for each pair, gets the line of the add step with `crypto_bls_miller_add`, and multiplies f by it.
- Gives the product of the `millerLoop` values: each `millerLoop` value f_i takes f_i^2 l_i at a double step and f_i l_i at an add step, and the product of f_i^2 l_i over the pairs is (the product of f_i)^2 times the product of l_i.

### Function never

- Writes more than `f`, the T_i of `pairs`, and `work` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 64 bytes on x86-64 (return address included), 96 bytes on ARM64, 112 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_miller_loop`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `f`, `pairs`, `count`, `work`.

## Function `crypto_bls_final_exponentiation`

Computes f^((p^12 - 1) / r) by the steps of `finalExponentiation`.

### Signature

```
crypto_bls_final_exponentiation(result, f, work) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `result` | output | `Fp12Element` |
| `f` | input | `Fp12Element` |
| `work` | scratch | 3456 bytes |

### Caller must

- Keep `result` and `f` out of `work`.

### Function does

- t = conj(f) / f, then m = frob(frob(t)) t.
- a = (m^((|x| + 1) / 3))^(|x| + 1), b = frob(a) conj(a^|x|), c = (b^|x|)^|x| frob(frob(b)) conj(b).
- Writes c m.
- Raises to the powers with `crypto_bls_fp12_cyclotomic_pow`. Each base is in the cyclotomic subgroup: m = f^((p^6 - 1)(p^2 + 1)), so m^(p^4 - p^2 + 1) = f^(p^12 - 1) = 1, and products, powers, conjugates and Frobenius images of m stay in that subgroup.

### Function never

- Writes more than `result` and `work` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 64 bytes on x86-64 (return address included), 96 bytes on ARM64, 112 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_final_exponentiation`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `result`, `f`, `work`.

## Function `crypto_bls_pairing_check`

Writes 1 when the product of e(P_i, Q_i) over the pairs is 1, else 0 (`pairingCheck`).

### Signature

```
crypto_bls_pairing_check(pairs, work, valid) -> nothing
```

### Arguments

| Name | Role | Type |
|---|---|---|
| `pairs` | input | `PairList` |
| `work` | scratch | 4608 bytes |
| `valid` | output | [`Valid`](secp256k1.md#type-valid) |

### Caller must

- Keep `work` apart from `pairs` and `valid`.

### Function does

- Skips a pair with a point at infinity.
- Takes the other pairs in groups of up to 4, in affine coordinates (`crypto_bls_g1_affine`, `crypto_bls_g2_affine`).
- For each group, gets the product of their `millerLoop` values with `crypto_bls_miller_loop`, and multiplies its conj into the product: conj of a product is the product of the conj values, so this is the product of conj(millerLoop(Q_i, P_i)). The BLS parameter x is negative.
- Runs `crypto_bls_final_exponentiation` once on the product, and compares the result with 1.

### Function never

- Writes more than `work` and `valid` and its own stack.
- Makes an OS call.

### Limits

- Stack of its own: 64 bytes on x86-64 (return address included), 96 bytes on ARM64, 112 bytes on RISC-V.

### ABI

- Role: L0.
- Symbol: `crypto_bls_pairing_check`, local to its object.
- Convention: the core ABI for each ISA (ARCHITECTURE.md section 6). It returns no status.
- Argument order: `pairs`, `work`, `valid`.
