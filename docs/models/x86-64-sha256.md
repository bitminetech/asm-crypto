# x86-64 SHA-256

The scalar core entry uses the System V AMD64 register convention on all three OS targets. The Lean image contains 901 instruction bytes followed by alignment, 64 round constants at offset `0x390`, and the eight initial hash words at `0x490`. The 1,200-byte image has SHA-256 `b022387787ecadcf7a4b1bdd10decabaa2cabff7ccfa158e2b24d5f1775a3a31`. The artifact check compares it with the `sha256.o` member of each baseline archive and checks the identity of the containing relocatable object. It resolves the symbol through the shipped archive indexes, including both COFF linker members. [Artifact check](../../tests/runner/check_x86_sha256_artifacts.py)

The local decoder reads the legacy long-mode encodings used by this entry, including the REX, ModR/M and SIB fields. A step selects an instruction at the current RIP, checks its bytes in the current machine memory and executes it with the pinned upstream semantics. The CPU state includes the flags and the oracle for undefined bits. Correspondence of the decoder and upstream semantics to hardware, and preservation of the image at final link and load, are trusted. [Decoder and fetch](../../lean/Models/X86SHA256Decode.lean) · [x86lean source](https://github.com/jyh/x86lean/tree/2a32a6ec0b5ddfe625f3720ac647082830390917)

The pinned objects have no relocations in the modeled text. Linux has a PC-relative relocation from `.eh_frame` to the entry. Windows has three `.pdata` relocations for the entry, function end and unwind data. Its unwind codes record the six pushes and 456-byte allocation in the first 17 instruction bytes. The macOS compact-unwind entry covers `0x385` bytes and selects the DWARF encoding. For ELF and Mach-O, the DWARF call frame address advances from RSP+8 at entry to RSP+512 after the prologue and returns to RSP+8 at RET. These are properties of the object metadata inspected with LLVM and fixed by the whole-object identities. The consuming application establishes final load addresses, unwind registration and runtime symbol binding.

## Equal candidate

`Crypto.X86_64.sha256.equal` proves the shared stateless baseline for the scalar entry under the documented x86-64 profile. The candidate uses the same predicate bundle as ARM64. Its expected statement and dependencies require independent review before CI can issue a checked receipt. The review generator writes the statement and manifest to `build/verification/x86-64-equal-review/`. [Baseline statement](../../lean/Proofs/X86_64/NativeEqual.lean) · [Review generator](../../tests/runner/prepare_x86_64_equal_review.py)

The whole-call observation is a list of fetched RIPs, decoded instructions and effective data operands in their execution order. Lean ties this list to the same execution that returns the reference result. Its sequence and addresses are functions of the symbol address, caller pointers, RSP, payload offset and length. Equal public calls therefore have the same list for arbitrary secret bytes and initial arithmetic flags or oracles. The stacked return address is public and determines the final RIP. [Call and observations](../../lean/Proofs/X86_64/Caller.lean) · [Public trace theorem](../../lean/Proofs/X86_64/NativeEqual.lean)

Independent grants cover the input header and used payload, the digest, code and constants, and the stack. Each issued fetch and data-operand byte has a proved range, canonical address and permission. Input reads are confined to the header and used payload even when the caller allocation has unused capacity. Stack writes stay below the original RSP and the return slot is read-only for this call. The observed instructions create no resource handles, retained borrows or pending accesses. [Ranges](../../lean/Proofs/X86_64/TraceSafety.lean) · [Grants](../../lean/Proofs/X86_64/NativeSafety.lean)

## Environment and target profile

The caller or its runtime reserves the 504 bytes below the incoming RSP and the eight-byte return slot through the first RET. The caller exclusively borrows the writable stack bytes and digest, and shares read-only input, image and return-slot bytes. The stack condition models an isolated reservation across OS callbacks. Handlers may run on separately reserved stack space. A handler that reuses the reserved portion of the interrupted stack requires a phase-sensitive environment model. The borrowing lifetime ends at the return boundary.

The scheduler may advance before each local instruction and modify unrelated memory. Resumption restores the local CPU context. A local instruction preserves every byte outside its reported writes in the incoming memory, including any progress the environment just made. Compatible invocations may share read-only bytes and can re-enter with their own stack and output reservations. The local access proof rules out races and dependence on unrelated concurrent work. No locks, waiting or OS completions occur in the function. Termination assumes each modeled resumption takes place. [Interleaving](../../lean/Proofs/X86_64/Interleaving.lean) · [Scheduled call](../../lean/Proofs/X86_64/NativeScheduled.lean)

A deployment supplies ordinary byte-addressable memory, stable access grants and a mapping to backing bytes that separates writable borrows from other live aliases. Physical environment actions are reported at every borrowed alias, including protection changes and releases. The backing-event theorem then excludes races and invalidation of live borrows. Review for each OS establishes that the loader, ABI adapter, stack preparation, exception policy, unwind registration and CPU meet the primitive correspondence laws. The platform bridge preserves omitted current-thread ABI state under those laws. [Backing memory](../../lean/Proofs/X86_64/NativeSafety.lean) · [Platform correspondence](../../lean/Proofs/X86_64/NativePlatform.lean)

For a timing profile, the cost at the actual architectural pre-state must depend only on the current instruction, its public memory operands and its next RIP. Lean proves equal local cost for paired calls under independent admissible schedules, using that per-instruction law. A physical timing claim requires processor evidence for the selected profile. The architectural observer models retired instructions and effective addresses. Caller preparation, scheduling, result use and residual secrets in caller-clobbered registers and private stack remain caller obligations. [Timing model](../../lean/Proofs/X86_64/Timing.lean)

## Callable theorem

`Crypto.X86_64.sha256_serial_contract` combines the reference result, ABI state, executable instruction boundaries, stack depth and operand observations for the same run. Its trace starts at the symbol, stays on the 200 decoded instruction boundaries, and finishes at the first RET. Lean proves the pre-instruction RSP at every boundary. The largest displacement below entry RSP is 504 bytes, giving a 512-byte footprint including the return slot. [Serial contract](../../lean/Proofs/X86_64/SerialContract.lean) · [Control flow](../../lean/Proofs/X86_64/ControlFlow.lean) · [Stack bound](../../lean/Proofs/X86_64/StackTrace.lean)

`Crypto.X86_64.sha256_serial` starts with RIP at the scalar symbol and ends at the first executed RET. It quantifies over the incoming CPU, arbitrary initial memory, a well-formed `ByteList` with fewer than 2⁶¹ used bytes and an independently supplied allocation extent. Its entry predicate specifies alignment, nonwrapping regions, separation, the loaded image, the header and payload, and canonical instruction and return addresses. The caller supplies these entry facts. [Statement and entry predicate](../../lean/Proofs/X86_64/Caller.lean)

The returned RAX is zero. The 32 bytes at the caller's output pointer equal the pinned byte-oriented SHA-256 reference, which the shared reference proof relates to FIPS. RIP equals the original stacked return address, RSP advances by eight and RBX, RBP and R12–R15 regain their original values. Every byte outside the output and 512-byte stack region retains its original value. The stack region includes the eight-byte return address. [Call result](../../lean/Proofs/X86_64/Caller.lean) · [FIPS bridge](../../lean/Proofs/Reference.lean)

For a payload of `n` bytes, let `r = n % 64` and let `p` be one when `r < 56` and two otherwise. The exact instruction count, including RET, is `106 + 6*r + (p-1) + 3975*(n/64 + p)` using integer division. The proof covers the empty payload, every tail length and arbitrary numbers of complete blocks. [Count and composition](../../lean/Proofs/X86_64/Body.lean) · [First-return semantics](../../lean/Proofs/X86_64/Fetch.lean)

The serial disclosure theorem compares calls with equal public pointers, length, offset and return target. If the two reference digests agree and the caller's public pre-call bytes agree, every returned byte outside the used payload and private stack agrees, as do status, RSP and RIP. Caller-clobbered registers and the private stack may retain secrets. The caller is responsible for protecting them and for its preparation, invocation timing and use of the digest. [Returned observations](../../lean/Proofs/X86_64/Disclosure.lean)

The proof constructs the sequence of actual loaded ISA steps. Every fetched byte falls within the executable prefix. The data-operand trace records the size, direction and effective address of each operand, including the implicit stack read of RET. [Operand semantics](../../lean/Proofs/X86_64/Observations.lean) Every executed instruction belongs to a scalar family with no calls or OS instructions. The direction flag, FS and GS bases, vector register file, MXCSR and the modeled MMX/x87 state are preserved. [Execution trace](../../lean/Proofs/X86_64/Execution.lean) · [Platform-state frame](../../lean/Proofs/X86_64/PlatformFrame.lean)

## Supporting proofs

- All 200 instruction boundaries decode. Internal branches and fallthroughs land on those boundaries, the only return is at offset `0x384`, and the embedded constants match the imported FIPS reference. [Image proofs](../../lean/Proofs/X86_64/Image.lean)
- The 20 instructions at `0x17f` compute a schedule word, store it at the indexed stack slot, and preserve the loop index and base registers. The 40 instructions at `0x204` implement one FIPS round, preserve memory, and advance RIP to the loop counter update. Both results quantify over incoming flags and the undefined-bit oracle. The input, expansion and round bodies also have paired public address traces. For every legal iteration index, their four-byte accesses fit the source block, schedule or constants, and their writes target the schedule. [Word traces and bounds](../../lean/Proofs/X86_64/WordTrace.lean) · [Fetched instruction proofs](../../lean/Proofs/X86_64/Fragments.lean)
- The three-instruction loop latch increments the index and branches on an unsigned comparison with the public bound. Its proof requires a canonical back-edge address. [Counter proof](../../lean/Proofs/X86_64/Counter.lean)

For an arbitrary block read through RBP, `block_loaded` starts at offset `0x16d` with RBX zero and stops at `0x2c2`. Its 3,969 fetched instructions read the 16 big-endian input words, derive the other 48 schedule words, load the eight working registers, run all 64 rounds, and add their results into the saved hash. The final eight stack words equal `SHS.SHA256.compress` of the original hash and input. The proof establishes the memory frame outside the 288-byte schedule and hash workspace. Its premises include separation of the image and workspace, separation of the source block from the schedule writes, and canonical loop targets. [Block theorem](../../lean/Proofs/X86_64/Block.lean)

For a phase of `n` blocks, `phase_loaded` proves termination after `3975*n+2` instructions and folds compression over the original memory in address order. It covers an empty phase as well. `switch_loaded` installs the padding pointer and block count. Given the FIPS-prepared padding bytes, `folds_reference` identifies the combined message and padding folds with the pinned byte-oriented SHA-256 digest. [Phase execution](../../lean/Proofs/X86_64/BlockPhase.lean) · [Phase switch](../../lean/Proofs/X86_64/PhaseSwitch.lean) · [Reference bridge](../../lean/Proofs/X86_64/PhaseReference.lean)

At entry, seven fetched instructions save RBX, RBP and R12–R15 and reserve 456 more bytes. At the digest exit, 25 fetched instructions write the eight hash words as 32 big-endian bytes and preserve bytes outside the output. The final nine instructions return zero, reload the six saved registers and transfer control to the canonical address on the stack. [Entry](../../lean/Proofs/X86_64/Entry.lean) · [Digest serialization](../../lean/Proofs/X86_64/Digest.lean) · [Digest through RET](../../lean/Proofs/X86_64/DigestReturn.lean)

## Section 8 obligations

| Requirement | Scalar x86-64 evidence |
|---|---|
| Reference and failures | Every valid call returns the FIPS reference digest and zero status. Initial output, unused input space and uninitialised stack bytes may vary. |
| Memory, permissions and lifetimes | Every fetch and data byte has a proved range and grant. Alias-closed environment reporting excludes invalidation and races for live borrows. |
| Termination, ABI and re-entry | Each permitted schedule reaches the first RET in an exact public-length count. The call obeys the 512-byte footprint and restores the documented registers. Re-entry uses compatible borrows. |
| Confidentiality and timing | Paired calls agree on branch and address observations. Final public bytes agree under equal permitted disclosures and public pre-call bytes. Each admitted cost model gives paired scheduled cost equality. |
| Effects and platform | Scalar leaf instructions carry no resource or OS effects. The native correspondence laws bind the verified run to the selected OS and loaded image. |
| Validation | The supporting runner audits the theorem, replays it in Lean and checks all three artifact identities. CI checks the externally selected statement and dependency pin before issuing the receipt. |

The SHA-extension archive has its own implementation and requires its own proof. Each external pin binds its registered source closure.
